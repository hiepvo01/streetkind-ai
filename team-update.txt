Other things found in the deep audit (not from your MRs but worth knowing)
---------------------------------------------------------------------------

A code review of the audio + transcript pipeline turned up four more
silent field-binding bugs in the Client form, identical pattern to the
age_group bug. The frontend tab read a typo'd or phantom field name
while the schema used the right one. Each bug below lists which schema
field, what the frontend was reading instead, and how many production
records it silently affected:

- emergencyServicesCalled was read as data.emergencyServices. ~454 records.
- clientServiceReferrals was read as data.serviceReferrals. ~94 records.
- clientConsciousness, clientValuablesVisibility and clientLostProperty
  were read through a phantom data.theftRisk.* namespace. ~688 records.
- injury was read as data.injuryRisk. ~1203 records.

All fixed in commit 1624319 plus bb24aea. The radio/checkbox values now
render correctly when you open any of those clients.

Plus a few smaller audit items shipped in the same round:
  - Yellow "Audio recording disabled" warning when the mic is denied
    (likely cause of your "have no voice record" report).
  - <audio> shows a fallback message when the signed URL is unavailable.
  - Transcripts fetch error is now visible instead of showing a fake
    "no transcripts" state.
  - 67 legacy clients with `safeBase` blob (lower-case b) now display
    correctly via a read-side normaliser.
  - 4597 client records had a `startTime` Pydantic was silently
    dropping on PUT. Schema field added.


New guardrails so this class of bug can't ship again
-----------------------------------------------------

Two test files now run on every commit:

- tests/test_field_binding_integrity.py runs 45 static checks (no servers
  needed) that compare every Pydantic schema field name, JSON config key,
  frontend tab data.<x> reference, and handleCheckboxChange('<x>') write
  to make sure they all agree.
- tests/e2e/test_ui_form_binding.py is a Playwright test that seeds an
  incident with every radio and checkbox set to a known value, opens the
  IncidentEditModal, navigates each tab, and asserts the actual <input>
  states in the DOM match what was stored.

If a future MR introduces another typo'd field name or schema/config
drift, these fail at commit time -- not in production.
