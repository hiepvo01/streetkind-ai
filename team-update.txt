What was wrong
--------------

These were all the same class of bug: the frontend tab read a typo'd or
phantom field name while the schema (and therefore the AI extraction +
the database) used the right name. The radios/checkboxes rendered
unselected even though the data was correct underneath. Production
record counts in parentheses were each invisible to users.

Client form bindings:
  - emergencyServicesCalled       read as data.emergencyServices       (~454 records)
  - clientServiceReferrals        read as data.serviceReferrals        (~94 records)
  - clientConsciousness/Visibility/LostProperty  read through phantom data.theftRisk.* (~688 records)
  - injury                        read as data.injuryRisk              (~1203 records)
  - ageGroup keys                 config used "from18to25", schema/AI use "18to25"  (4607 records)

SafeBase regression introduced by the age_group fix:
  - GenderAgeCount uses "from18to25"/"from26to39" but the prompt was
    listing the unprefixed client keys after the age_group fix. AI was
    producing keys Pydantic silently dropped.
    Fix: safebase.json overrides shared.json with from-prefix keys.

Frontend wiring:
  - generateIncidentNarrative + reverseGeocode bypassed apiUrl(),
    so they 404'd in cross-origin prod (Magic-generate + Use my location
    were broken).

User-facing silent failure modes:
  - Mic permission denied was a silent catch -- volunteer got no audio
    saved with no feedback. Likely cause of the "have no voice record"
    report. Fixed: yellow "Audio recording disabled" warning surfaces.
  - <audio> rendered empty when signed URL minting failed. Fixed:
    explicit warning Message when audioPath exists but URL doesn't.
  - fetchIncidentTranscripts failure showed "no transcripts were
    recorded" -- a flat lie. Fixed: separate transcriptsError state.

Backend correctness:
  - 67 legacy clients had a `safeBase` blob (lower-case b) the UI
    ignored. Fixed: _normalise_legacy_client folds into safeSpace on
    read.
  - 4597 client records carry a startTime that Pydantic was silently
    dropping on PUT (field wasn't in schema). Fixed: declared as
    Optional[int] = None.
  - Two client schemas had hidden type-coercion brittleness in the
    radio comparator. Fixed: String() coerce in RadioGroup.


How this slipped past the previous tests
-----------------------------------------

The earlier suite verified API contracts (round-trip JSON via API)
and UI element existence (button visible, modal opens). It NEVER
asserted that the values inside form inputs matched the stored data.
Every binding bug above looked fine to the old tests because the
correct JSON was sitting in the debug accordion at the bottom of the
form -- the bug was that nothing else read it.


New guardrails
--------------

Two test files added that fail at commit time on this class of bug:

1. tests/test_field_binding_integrity.py  (45 static checks, no servers)
   - For every nested-boolean section: schema name === JSON config key
     === data.<x> read === handleCheckboxChange('<x>') write
   - For every flat-int radio: schema name === data.<x>
   - Schema sub-fields exactly match JSON option keys (no extras, no
     missing)
   - SafeBase prompt's listed age groups equal GenderAgeCount fields
   - Incident prompt's stated ageGroup keys equal client schema contract
   - No fetch() in frontend/src bypasses apiUrl()
   - createBlankClient declares exactly the schema's top-level fields

2. tests/e2e/test_ui_form_binding.py  (Playwright)
   - Seeds an incident with EVERY radio + checkbox set to a known
     value, opens the IncidentEditModal, navigates each tab, asserts
     the actual <input> states match what was stored.
   - This is the test that would have caught every binding bug above.
