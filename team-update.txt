Voice + audio storage (already shipped, prior round)
-----------------------------------------------------

If you were looking for the voice recordings: they are NOT in RTDB
(transcripts/ holds the text + a path pointer only). The audio blobs
live in Firebase Storage:

  https://console.firebase.google.com/u/1/project/streetkind-app-dev/storage

Inside the bucket: audio/<incidentId>/<transcriptId>.{webm|m4a}

Why split: RTDB charges per-byte read on every fetch, bad for ~1 MB
audio. Storage is built for binary blobs and supports signed URLs.

Privacy model: blobs are private. The backend mints fresh 1-hour v4
signed URLs on read (see signed_audio_url() in firebase_client.py).
A leaked URL expires. RTDB stores only the blob path, never a long-
lived URL. Old records that still have a public-URL `audioUrl` keep
working via the legacy fallback in get_transcripts_for_incident().

Endpoints to integrate against (all hierarchy-scoped):
  POST /api/forms/incident/{id}/transcripts            create transcript
  POST /api/forms/incident/{id}/transcripts/{tid}/audio multipart audio upload
  GET  /api/forms/incident/{id}/transcripts            list (each gets fresh signed URL)

explicitly asserts (against live prod):

  - RTDB stores audioPath only, no long-lived URL

      `audio/<incidentId>/<transcriptId>.(webm|m4a|ogg|mp3|bin)`
  - Admin SDK confirms blob exists at that path with matching size
    + audio/* content-type
  - Signed URL serves byte-exact uploaded data
  - Same blob without signature is denied (401/403/404)
  - Incident delete wipes both RTDB record and Storage blob
